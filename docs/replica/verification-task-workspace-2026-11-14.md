## 新增链路如何验证

新增桌面用例使用本地合成 OpenAI 兼容流式接口，经真实 Provider、Tool Surface 和 Agent 调度执行九步工具调用。未用直接计算 IPC 代替聊天工具链。固定 Excel 中 `0.1 + 0.2 = 0.3`，另一分组为 `8`；检查真实保存的运行、候选、正式状态和两份 ready 报告，再通过原生保存流程核对 PDF 文件头和冻结 JSON。数值依据核对到 C2／C3；源文件移除后，第二种格式仍从已发布冻结数据生成。最后从聊天手动修改标题，验证任务列表及分析标题同步、搜索、固定／目录保持，以及重启后仍关联同一会话。

回归保护还覆盖：并发开启只建立一个关联、已有记录保留、跨任务来源拒绝、成功调用不重复计算、同一调用标识换参数拒绝、重启中断记录、错误参数和不兼容视图拒绝、输入单元格独立分页、来源变化拒绝发布、模型切换后拒绝旧确认，以及停止／退出不保存半次运行。渲染通知失败不会回滚已经提交的来源快照；报告取消会记录为失败调用，不作为已生成成果返回。

候选确认需要同一会话、当前模型标识、匹配候选摘要，以及完整读取响应中生成的随机 `reviewReceiptId`。仅持有提交阶段的摘要不能确认，避免工具输出因上下文不足未送达时仍绕过读取步骤。模型语义上的业务复核质量仍需另验，不以随机凭据替代业务判断。

新链路测试模型明确配置为 131072 上下文、8192 输出；没有移除应用的上下文检查。真实使用应按所选模型能力配置，不能虚报容量。普通聊天文本仍与保存的正式分析结果区分。
