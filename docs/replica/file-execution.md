# 文件代码执行与完整结果登记

基线：SemaPath 0.2.19。当前接通 R02 的附着式终端执行、`PBI_RESULT_PATH` 表格登记和已有分析/发布/报告链路，不代表全部开放执行协议完成。

## 工作台使用

1. 在任务中登记实际 Excel/CSV，配置支持工具调用的模型，进入同一任务的“对话”。
2. 对需要代码的计算直接提问。Agent 应先读取任务来源/结构；可用时加载 xlsx 技能。当前仍需真实模型业务样例验收，不保证所有模型都会正确选择工具。
3. `exec` 声明 `fileInputs`（建议使用 `datasource_context` 返回的 `sourceId`，也接受已登记文件的 `path`）以及已知的 `sheet`/`range`，设置 `fileOutput="table"`。
4. 原生运行时提供 `PBI_INPUTS_PATH`，其 UTF-8 JSON 中的 `inputs` 包含实际路径及捕获版本；代码须读取真实文件计算。运行时同时分配独立的 `PBI_RESULT_PATH`。
5. 代码将完整结果写入结果文件，标准输出只用于日志。Agent 必须检查 `tableDelivery`；命令退出成功不能替代完整结果登记。
6. `ready` 返回的表格来源 ID 可用于已有 `datasource_query(kind="file")`、九方法、十四图型、`analysis_evidence`、候选读取/确认与 PDF/JSON 导出。

示例交付格式：

```json
{
  "complete": true,
  "tables": [
    {
      "title": "区域销售额",
      "columns": ["区域", "销售额"],
      "columnTypes": ["text", "number"],
      "rows": [["华东", "0.30000000000000000000"]]
    }
  ]
}
```

`columnTypes` 可省略；支持 number/text/boolean/date。数字建议写字符串，原始 JSON 数字使用原始词法文本读取，避免大整数先转成 IEEE 双精度。保留 null、布尔及有效 ISO 日期；Excel 日期对象支持 type/serial/format/date1904，原始 serial 和格式也保存在依据中。不同粒度应分不同表，标题和字段使用用户语言。

## 登记、依据与权限

- 复用既有终端权限、命令授权和进程管理，不新增绕过权限的执行器，也不是新的操作系统沙箱。结果可登记的声明输入限定为当前任务已登记文件；输入声明与文件指纹不能证明程序实现了正确业务逻辑。
- 登记前后检查来源 ID、指纹和任务归属。每个结果标为 `file_execution` / `recorded_result` / `not_captured`；结果表单元格是程序输出，不能冒充原始业务明细或捏造到原 Excel 单元格的一对一映射。
- 保存执行命令、实际输入版本、技能加载状态、结果与单表摘要、完整规范化表。命令摘要不是外部脚本内容摘要，外部脚本/依赖环境未被完整捕获，因此不声称可重放。公开来源中的已知输入路径和工作目录用标识替换，原命令仅在私有本地执行账本保留。
- 解析/工作簿构造在已有受限 Worker 中完成。全部表先验证再原子登记；部分结果、非零退出、超时、缺文件、乱码、重复字段、错列/类型和输入变更不会登记半套来源。
- 后续计算及发布继续核对代码输出的声明输入版本。发布后冻结报告保留当时执行来源与完整表，不重新执行代码或读取已删除输入。

## 状态与恢复

相同会话/消息/调用标识与相同参数返回已存结果，不再次执行；替换参数拒绝。未启动的授权请求保留准备状态，实际派发后标为运行中。停止会终止附着的进程，失败不产生可发布依据。

重启时，未完成调用标为中断；若全部来源已在退出前原子提交，则恢复已保存交付，不再计算。Agent 可用 `analysis_get(executionId, tableIndex?, offset?, limit?)` 分页读取执行结果，默认每页 50 行。完整输出仍保存在任务来源与冻结依据中。

当前运行时工件分别在独立用户目录的 `analysis-executions`、`analysis-datasets` 和 `analysis-reports`；不是源码交付资源。原 R19 的完整备份/换机恢复缺口仍需补齐这些受控文件及路径迁移，不能用单机重启验收代替。

## 约束与后续范围

- 本批表格执行保持附着、可取消，最长 120 秒；不接受 background/yieldMs 或 Programmatic stdin。普通日志命令沿用原后台执行行为。原版长期后台表格执行与 process 完成联动尚未补齐。
- 原始结果最多 32 MiB、100 张表、每表 256 列；当前分析引擎另有每表最多 50,000 数据行、全结果 500,000 单元格、单个生成工作簿 20 MiB 的边界。超限明确失败，不保存截断表。
- xlsx 技能状态来自当前执行上下文，不接受模型自行声称已加载。按需方法知识、使用声明、指标口径库、完整参数修复编排/预算、富正文/业务图/报告工具仍为后续工作。
- 不执行 Power BI 模型写回，不改动云端权限。真实模型、PBIX、云租户验收及两项用户暂缓决定继续单列。

## 既有界面中的变化

```text
BEFORE 数字依据 → 文件 / 查询快照 / 关联来源
AFTER  数字依据 → 文件 / 查询快照 / 关联来源 / 文件代码执行结果
                                              ├ 声明输入版本
                                              ├ 执行命令与摘要
                                              └ 已记录输出的核对边界
```

沿用 DataOrigin 的线性信息与主题变量；长命令使用可展开区域和换行，指纹使用等宽字体，保留键盘焦点。ui-ux-pro-max 的长文本 UX 结果适用；两次 Vue 专项检索无匹配，组件实现沿用本仓库已验证的 Vue/details 模式，没有另建视觉系统。
