# 自然语言取数与分析设计

## 范围

在当前任务的已有连接上增加模型驱动的只读取数，复用现有快照、计算、依据和报告。用户选择允许使用的任务连接，可额外选择已有文件；模型根据真实结构选择连接和查询。最多三次取数、一次显式关联，再进入既有规划/完整计算/复核。缺少结构、业务定义或权限时澄清，不猜测。暂缓的 Entra/Fabric 配置不改变。

## 执行与持久化

一次请求持有任务修改锁，连接会话固定配置/模型绑定及账号，统一取消信号。远程只返回快照载荷，不在连接服务中再次进入任务修改锁。临时快照由同一个任务事务创建，计算与复核成功（或有效澄清）后一次保存来源、取数记录、运行和回答。失败/取消清理本次创建的文件，已有任务不被半成品覆盖。

模型只取得公开连接标识、库/模型名和完整但有上限的结构，不取得主机、用户名、密码、令牌或认证缓存。自动 SQL 在既有只读事务/语句检查之外，使用 AST 限定访问结构中列出的当前数据库表；不以正则猜测表边界。Power BI 固定模型，结构不可读时不自动生成猜测 DAX。

取数结果不截断冒充完整数据；整数/十进制仍为字符串。模型生成查询的身份、问题、结构摘要及实际 SQL/DAX 随来源冻结，并沿关联根来源保留。图表和正式答案继续由实际计算值引用生成，报告不重新请求模型或在线数据。

## 边界与恢复

已有文件模式保持原合同。锁定输入行的下钻不能发起在线取数扩大范围。在线分析全局预算最多十次模型调用、三次成功取数、一次关联及五分钟；单次连接/查询保持现有更短时限。连接变更/账号退出使旧会话失效；进入最终原子保存后不再接受取消。云端取消仍只表示本地停止等待。

若取数后需要业务澄清，保存已取得的完整快照及澄清记录，供用户继续；执行错误和取消不提交部分来源。真实业务模型理解与真实微软环境仍单独验收。

## 验收目标

真实独立 MySQL 和 Electron：自然语言→结构→模型 SQL→精确快照→本地计算→依据→发布/报告；覆盖跨库拒绝、只读拒绝、无结果、失败/取消原子性、改配置、重启及源移除后报告。Power BI 使用既有原生协议/微软合成边界验证相同工程路径，不冒充真实 PBIX/账号验收。普通文件模式和既有十条桌面流程回归。
