# 任务工作台与分析工具接口

目标基线为 SemaPath 0.2.19。本轮落实 R01／R02 的统一任务与分析工具接入：同一任务可进入聊天、分析、文件、依据和成果；聊天 Agent 通过真实运行时调用现有计算与发布服务。原有分析任务和发布记录保持可读。

## 数据与运行边界

聊天会话与分析记录使用持久的一对一关联，分别保留原有主键，不复制或合并历史记录。旧分析任务在首次打开聊天时创建关联；已有聊天会话在进入分析工作台时登记分析记录。SQLite 唯一约束防止一个会话关联多个分析任务。关联的会话删除后保留历史分析，明确提示会话已失效，不静默改绑。

会话标题和工作目录作为关联后的统一元数据。任务列表支持搜索、固定及恢复；既有聊天的编辑、分支、导出和输入草稿沿用原运行时。分析使用当前任务已登记的来源和连接；工具参数不能指定其它任务、替换账号或授予连接权限。

分析工具经 AgentToolManager／ToolService 注册、发现和调度，保留原有权限、执行日志、停止与 Tool Surface 约束。分析接口包含上下文、结构、文件计算／受限 SQL／DAX 与关联、依据、方法与图表契约、问题框架、进度、候选、确认及报告导出。只声明已实现的接口，不提供虚假的自由图、指标库、模型写回或自定义报告能力。

工具调用以会话、消息和工具调用 ID 关联持久执行记录，记录规范参数摘要和执行结果；同一标识不同参数拒绝，成功调用重放已有结果，未完成调用先核对保存状态，不能自动重复有影响的操作。取消信号进入 Worker 和连接器，最终保存阶段遵守既有原子边界。

聊天工具在合法普通会话中保持稳定可发现；首次调用可为该会话登记分析记录，不自动绑定外部账号或添加文件。上下文和候选不发送原生文件路径或完整原始快照载荷；候选包含全部计算输出值，原始输入单元格通过独立分页读取并显示总数及后续页状态。保存的数据与冻结报告仍含完整依据；单次工具响应上限 8 MB，超限不能获得已读确认。

候选只接受已登记实际运行和视图引用。提交返回候选标识；同一会话／模型必须再次读取完整候选，并携带该响应中的随机已读凭据才能确认。凭据只在完整读取响应中提供，避免工具结果因上下文不足未送达时仍仅凭提交摘要确认。确认重新检查候选、运行和来源版本。报告仅从已发布版本冻结生成，不重新取数；主进程工具作业通过自己的取消信号管理生成周期，渲染失败或取消不作为成功成果返回。当前受控算法与数据限额保持；任意代码结果登记和原版全部富正文／自由图协议继续按独立工作包推进，不以通用终端底座冒充完成。

## 界面

BEFORE:
应用侧栏 → 聊天会话
独立分析页 → 分析任务 → 数据／分析／依据／报告

AFTER:
统一任务列表与搜索 → 同一任务
                    → 聊天（现有 ChatPage 与工具过程）
                    → 分析／数据依据／任务文件／报告与成果
                    → 同一标题、目录、数据版本与历史

界面沿用现有蓝色、浅深色、字体和线性工作台。任务切换、空模型、失效会话、后台执行、失败及重启均需有明确状态；切换或异步更新不得把一个任务的数据显示到另一任务。

## 验收

完成实现后增加持久化、唯一关联、来源／会话隔离、重放、候选读取确认、取消及恢复的必要回归；真实 Electron 验证聊天工具计算到依据、发布和冻结报告，并复验原有分析流程。模型和 Power BI 合成协议只证明工程链路，真实业务模型／PBIX／云端账号验收继续单列。类型、静态、国际化、格式及界面终审完成后更新使用文档和范围账本。
