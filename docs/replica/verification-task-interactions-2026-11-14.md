## 隐藏 Electron 验收

四条流程分别通过，并非声称全产品 E2E 套件在本轮全部重跑：

1. Excel 导入 → 精确计算 → 单元格依据 → 图表 → 正式发布 → 重启 → 文件版本变化保护与跨任务拒绝。原脚本曾期待重启清空单位，现按新增恢复行为核对 `1.3 元`，复验通过。
2. 统一任务对话 → 实际 Agent 工具分发 → 计算与依据 → 完整读取候选和复核凭据 → 发布 → A4／演示版冻结报告 → 重启。模型协议使用本机合成 HTTP 服务，没有使用用户模型密钥。
3. 五类引导和离线示例 → 实际 Excel 计算值选区追问 → `@销售额` 引用 → 跨任务引用草稿与侧面板恢复 → 模型实际调用 `analysis_get(contextId)` → 消息引用详情 → 助手原文追问 → 重启恢复与引导状态保留 → 文件不可用时显示明确状态。
4. 本机隔离 MySQL 的只读结构读取 → 只有连接、没有文件快照时数据“已就绪”且文件“待完成” → 修改为已关闭的回环端口 → 重新检查后数据“暂不可用”、文件仍“待完成”。读取前后任务来源数为 0，没有生成数据快照；实例正常关闭，端口与自有 Z: 映射已清理。

采集浅色 1440×1000、深色 1280×1000 和最小验证桌面尺寸 900×640，覆盖引导、引用候选、引用草稿、恢复的侧面板、引用详情、文字工具条和来源不可用七个状态，共 21 张原始图。每个截图状态均检查 Electron 可见窗口数为 0 和文档无横向溢出。窄聊天区域的状态栏在首轮自查中发生控件重叠，现按可用宽度换行，并增加模型／权限按钮不相交的布局断言。

最后的状态栏矩阵复验与立即退出恢复均通过，`e2e-handoff.log` 记录 1 条完整流程通过（2.0 分钟）；引导修正后又以 `e2e-final-review.log` 复验通过（1.2 分钟）。382 项回归后已核对最终构建。第二次自查确认 900 像素下两组控件分行、发送入口可见；21 张冻结证据保存在 `review-final`，尺寸与 SHA-256 记录在 `capture-facts-final.json`。静态设计检测仅执行一次，返回 `[]`、退出码 0。
