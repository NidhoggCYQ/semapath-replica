# 分析方法、统计图与数据依据

## 当前入口

在任务中登记 Excel/CSV 后，可以直接提问，也可以在手动计算的“口径”中选择分析方法。原有基础汇总保留。新增方法使用同一套 Worker、版本校验、候选发布和报告链路。

模型只提出结构化计划和复核决定；所有数值由完整筛选范围内的本地算法产生。方法名称不能替代实际计算。结果保存规则版本、适用条件、检查状态、精确表达式及原始单元格；图形坐标允许近似，精确数值与依据不由图形反推。

## 九种方法

| 原版 ID | 当前 Excel 执行路径 | 关键边界 |
| --- | --- | --- |
| cycle-analysis | 日、周、月、季、年聚合；真实时间间距；相邻期间差额与变化率 | 缺期断线且不补零；期间完整性单独声明；负/零基期保留说明；不凭短历史认定季节性 |
| structure-analysis | 单一分类和真实联合分类；记录数/金额、构成份额、正负贡献及总量对账 | 只接受 sum/count；记录数不冒充去重人数；负值不用饼环或百分比堆积；业务可加总性需指标定义支持 |
| stratification-analysis | 业务阈值或样本四分位数分层；样本量、均值、极值、直方分布与箱线 | 左闭右开；Type 7 分位数，重复分界合并；Sturges 等宽分箱，末箱含右端；1.5 IQR 保留离群值 |
| matrix-analysis | 同行 X/Y 配对、业务或样本中位数阈值、四象限计数、可选气泡规模 | 等号归入高侧；显式对象标识须非空唯一；探索分界不冒充目标；两轴的业务含义保留待核实 |
| metric-decomposition | 已定义的加法/乘法/除法恒等式；逐对象计算、残差、加法因素堆积与瀑布 | 定义来源必填；ratio 仅两因素；零分母不补值；非加法因素不当贡献；残差可见 |
| funnel-analysis | 同一对象一行的阶段 0/1 标记，逐行嵌套检查，相邻与总体转化；或无流失流程的步骤时长与累计均值 | 人群去重、窗口和成熟度分开核实；阶段反增不画有效漏斗；时长路径不计算人数转化率 |
| correlation-analysis | Pearson 与含并列平均秩的 Spearman；完整配对、缺失计数、散点与可选规模 | 常量或少于两对不伪造系数；整数/分数统计量精确，开方系数近似；不附带显著性、预测、因果或滞后断言 |
| label-analysis | 来源字段标签或有依据的 AND 规则；真实联合标签；规模、指标、记录份额、重叠与未知 | 不从独立汇总猜交集；保留空组/重叠；规则标签不冒充预测；重叠组不包装为互斥构成 |
| mece-decomposition | 当前分类层的逐记录归属、重叠、遗漏、剩余组和可加总总量核对 | 多重归属单列、不重复累加；空白/未匹配保留；金额对账不证明分类完备或原因成立 |

以上是九种方法在当前 Excel 引擎中的可执行路径。原版方法是开放式分析知识与 Agent 工作流，不等于九个固定统计算法；当前 Excel 的问题框架、父子路径及受控递归下钻已接入，见 analysis-framework.md；原版完整自由业务图、全量 Agent 协议、跨表/SQL/Power BI、任意代码及扩展方法组合继续单列开发。本轮不把这些剩余项改称已完成。

## 十四种图表与表格

line、bar、waterfall、scatter、bubble、funnel、stacked、percent_stacked、pie、donut、histogram、boxplot、heatmap、table 均有结果绑定与渲染实现。

图型按方法和实际数据提供，不把一个单值强行画成分布或相关图。柱/条、瀑布、堆积和热力在较多分类时分段展示；饼环保留完整组成与精确表；散点/气泡保留每个有效观测；箱线统计来自原始观测。气泡面积对应非负规模，零规模不伪造面积。百分比堆积按每个分类自己的系列合计计算，分母和精确比例有独立依据。

结果视图中可以切换适用图型查看；这只是查看切换。报告使用所选发布版本保存的图型。需要以另一图型正式交付时，在计算口径中选择该图型并计算、发布新版本。

当前采用自有 TypeScript/SVG 编译器，界面和 PDF 共用，不新增图表依赖。所有来源文字转义；链接只指向本结果的依据，不执行数据中的 HTML 或外部地址。

## 追溯与报告

1. `AnalysisPlan.study` 保存方法、图型、字段、阈值、来源、规则和必要的观察窗口。
2. Worker 从同一份已校验 SHA-256 的原文件计算，`AnalysisRun.study` 保存结果表、检查和图形绑定，所有数字通过 valueId 引用。
3. 每个值保留原始单元格、十进制原值、精确分数与公式；点击数值或图形标记进入现有数据依据面板。
4. 自然语言方法视图必须绑定实际方法查询，同一模型基于真实结果和自检再确认；整次回答原子发布。
5. A4/16:9 PDF 复用冻结的发布结果，保留方法条件、自检、图表、精确表和依据附录；JSON 保存完整输入。导出不重新读取 Excel 或请求模型。

报告渲染器为 analysis-report/2，新版缓存与旧版区分；analysis-report/1 元数据和冻结成果继续可读、可恢复，不改写旧 PDF。

## 资源与计算边界

- 单次方法最多 2000 条筛选后记录、100 个分类、28 MB 结果。超限明确失败，不以抽样结果冒充完整分析。原有基础汇总的文件/行限制保持。
- 任意缺失不自动补零。分层、矩阵、相关、指标关系及流程采用声明字段的完整记录，缺失数量保留。对象列一经指定需非空唯一；未指定时以行作为观测，业务粒度为待核实。
- 同一规则内条件为 AND；多个标签可以重叠。手动入口提供常用单条件规则，模型契约支持每条规则最多 5 个 AND 条件。
- 报告仍受 32 MB 冻结 JSON、8 MB HTML、50 MB/200 页 PDF 和 120 秒生成上限约束。超出排版/数值范围会明确失败或使用精确表，不交付截断内容。
- 自然语言协议仍限 6 查询、8 视图、4 次模型调用及既有上下文上限。缺乏定义时应澄清。合成接口验收只证明协议、计算和界面链路，真实模型语义效果需要业务表验收。

## 来源与实现位置

基线来自本机只读 SemaPath 0.2.19：analysis/catalog.json、9 个 pbi 方法资源，以及 PowerBiChartInputSchema 的 14 类型和适用性字段。规则版本对应基线知识版本（5、13、6、12、3、6、4、5、11）；本工程保存独立撰写的执行摘要和实现，不复制原版安装包、用户配置或凭据。

- shared/analysisStudy.ts：方法/图型契约与版本规则。
- main/analysis/studyMath.ts、studyEngine.ts：精确运算与方法算法。
- shared/analysisChartSvg.ts：界面与报告共用的安全图形编译器。
- renderer/components/analysis/MethodForm.vue、MethodAnswer.vue：字段/规则设置与结果。
- main/analysis/reports/：已发布数据冻结、PDF、依据与成果管理。
